# ADR 0003：线协议第 1 版与信任边界

- 状态：Accepted
- 日期：2026-09-30
- 关联：ADR 0001、ADR 0002
- 参照：codex `exec-server-protocol`（Apache-2.0）

## 背景

ADR 0002 定了「宿主侧客户端 + 线协议 + 沙盒内守护进程」的分层，没有定协议本身，也没有说清三个后端各自守的是哪条边界。第一版实现时需要把这些定下来。

## 决策

1. **协议第 1 版**：JSON-RPC 2.0 消息形状，按行分隔，一行一条；二进制内容 base64 编码。先 `initialize` 握手核对版本，版本不符直接拒绝。方法只有两组：进程（`process/start`、`process/kill`，输出与退出走通知）和文件（`fs/*`）。完整清单在 `src/taifeng_sandbox/daemon/protocol.py`。
2. **守护进程单文件、只用标准库、兼容 Python 3.9+**。宿主把源码经 `python3 -c` 注入执行环境，镜像里不需要安装本包。守护进程自带一份协议常量，由测试守护与协议模块一致。
3. **退出通知排在该进程全部输出之后**。守护进程读完两路输出、等到进程退出，才发 `process/exited`，宿主据此可以在收到退出通知时认定输出完整。
4. **连接即生命周期**。连接关闭（含宿主崩溃导致的管道断开）时，守护进程杀掉名下全部进程再退出。
5. **三条边界各管各的**：

   | 边界 | 由谁守 | 守什么 |
   | --- | --- | --- |
   | 进程能碰什么 | 执行环境本身（seatbelt 配置、bubblewrap 挂载、容器） | 文件读写范围、出网 |
   | 宿主经文件方法能碰什么 | 守护进程的根目录约束 | 解析符号链接后仍须在根目录之内 |
   | 命令该不该执行 | taifeng 工具层 | 审批、黑名单、超时、截断（ADR 0001 决策 2） |

   守护进程不约束进程的工作目录：进程一旦启动，能碰什么由执行环境决定，限制起始目录不增加隔离，反而让只读挂载的 skill 脚本无法在自己目录下运行。
6. **隔离后端不可用时失败，不降级**。找不到 `sandbox-exec`、`bwrap`、`docker`，或容器里的守护进程连不上，一律抛 `SandboxUnavailableError`（`OSError` 子类），由 taifeng 工具层转成 `spawn_error`。
7. **本机后端以新会话启动进程，强杀作用于整个进程组**，避免 shell 派生的子进程在强杀后继续运行。
8. **宿主侧输出缓冲有上限**（默认每路 16 MiB），超出部分丢弃并计数。taifeng 工具层会再按自己的上限截断；这里只防失控输出耗尽宿主内存。

## 否决的方案

- **守护进程做成需要安装的包**：每个镜像都要预装并跟着本仓升级，镜像由业务方提供时做不到。
- **守护进程约束进程工作目录**：见决策 5。
- **隔离后端不可用时退回本机直接执行并告警**：告警没人看，等于在没有隔离的情况下执行了模型给的命令。

## 后果

- 协议的不兼容变更必须升版本号，守护进程与客户端同步发布。
- 本机后端的输出在进程结束后一次性取回，不是流式；`CommandProcess` 协议目前也没有流式读取的接口。
- bubblewrap 后端没有叠加 seccomp 与 Landlock，隔离强度弱于 codex 的 Linux 沙盒；需要更强隔离时用容器后端。
